# Kargul 工作台 使用说明

面向员工、主管和管理员的完整操作手册。界面默认中文，可在「设置 → 通用 → 语言」切换中英文。

---

## 1. 快速开始

### 1.1 访问

- 线上地址：<https://calender-app-zh.pages.dev>
- 本地开发：`npm run worker:dev` 后打开 <http://localhost:8787>

### 1.2 注册与登录

1. 打开地址后看到登录页，点「注册」
2. 填写姓名、邮箱、密码（至少 8 位）
3. 提交后自动登录，并生成一份演示数据（15 个日历事件、9 条休假申请、12 个节假日、3 张发票等）

同一邮箱只能注册一次；忘记密码目前需要管理员在数据库层重置（见第 10 节）。

### 1.3 三种角色

| 角色 | 能看到什么 | 能做什么 |
|---|---|---|
| 员工 | 只有自己的数据 | 请假、记工时、开票、改资料 |
| 主管 | 自己 + 直属下属 | 在「团队审批」批准/拒绝下属申请 |
| 管理员 | 全员数据 | 主管的全部权限 + 修改任何人的角色和直属上级 |

- 注册时，邮箱在 `ADMIN_EMAILS` 环境变量里的账号自动成为**管理员**
- 其他账号默认是**员工**，由管理员在「团队审批 → 成员」里提升

## 2. 界面导航

- **左侧边栏**：主菜单（仪表盘、数据分析）、个人（资料、文档、休假、工时、福利）、付款（发票、收款方式）、设置
- **管理组**：只有主管和管理员能看到「团队审批」
- **顶部栏**：全局搜索（⌘K）、通知、帮助、快捷「申请休假」按钮
- **账户菜单**（左下角头像）：个人资料、设置、退出登录
- **深色模式**：侧边栏开关，或「设置 → 外观」
- **语言**：「设置 → 通用 → 语言」即时切换，演示数据会跟着翻译，你自己输入的内容不变

### 常用快捷键

| 按键 | 作用 |
|---|---|
| ⌘K | 全局搜索 |
| N | 新建日历事件 |
| R | 申请休假 |
| T | 回到今天 |
| ← / → | 上一/下一周期 |
| D / W / M | 日 / 周 / 月视图 |
| ⌘Z / ⇧⌘Z | 撤销 / 重做 |
| ? | 查看全部快捷键 |

## 3. 休假（核心功能）

### 3.1 日历

- 支持日、周、月三种视图；手机上显示以选中日期为起点的 3 天
- **拖拽空白处**创建事件；拖动事件改日期/时间；拖事件底边改时长
- 重叠事件自动并排显示
- 全天事件和法定节假日显示在顶部单独一行
- 点击事件打开详情，可编辑、复制、删除

### 3.2 申请休假

1. 点顶部「申请休假」或按 `R`
2. 选择休假类型：休假 / 病假 / 调休 / 半天假 / 事假
3. 选择开始/结束日期；关闭「全天」可申请某一天的部分时段
4. 填写备注（选填），提交
5. 提交后生成一条「待审批」申请，并在日历上生成对应事件

**天数怎么算**：只计算工作日，自动跳过周末和法定节假日；部分时段按小时折算（8 小时 = 1 天）。

### 3.3 余额规则

```
可用 = 合同天数 + 结转天数 − 已批准天数 − 待审批天数
```

- 已批准但还没到日期的假期计入「即将到来」
- 合同天数、结转天数可在「设置 → 休假」调整
- 节假日不计入任何扣减

### 3.4 我的申请

「休假」页下方表格支持搜索、按状态/类型筛选、排序；每行可以查看详情、编辑、取消、删除。主管也可以在详情里用「主管预览」模拟审批（仅演示，不改变真实状态）。

## 4. 团队审批（主管 / 管理员）

入口：侧边栏「管理 → 团队审批」，或直接访问 `/admin`。

### 4.1 处理申请

- 「待审批申请」列出你可见范围内的所有待审批请求
- 点「批准」或「拒绝」：
  - 申请状态立即更新
  - 申请人的日历事件同步更新（批准后备注变为「已批准」，拒绝后事件删除）
  - 申请人收到一条站内通知

**可见范围**：主管只能看到自己和自己直属下属的申请；管理员能看到全员。

### 4.2 成员管理（仅管理员）

「成员」表格里可以直接修改：

- **角色**：员工 / 主管 / 管理员（下拉即时保存）
- **直属上级**：选择谁是谁的主管，决定审批可见范围
- 表格同时显示每人的可用天数、待审批数量

管理员不能把自己降级（防止把自己锁在门外）。

## 5. 个人资料与文档

### 5.1 个人资料

可修改姓名、缩写、邮箱展示、电话、职位、部门、主管、地点、入职日期、生日、地址、紧急联系人、个人简介。

- 修改后点右上角「保存更改」；未保存时底部会出现保存条
- 生日必须早于入职日期；邮箱需要合法格式
- 这些资料只对你和人力资源可见（原型内的提示文案）

### 5.2 文档

- 支持拖拽上传或点「上传」，分类：合同 / 工资单 / 政策 / 医疗 / 税务 / 其他
- 可以搜索、按类别筛选、收藏、重命名、移动分类、删除
- 可以导出文档清单为 JSON

> 注意：演示版只保存文件名、大小、分类等元数据，**不保存文件内容**；刷新后无法下载原文件。

---

## 6. 工时追踪

- **计时器**：选择项目和任务，点「开始」计时，点「停止」自动生成一条工时记录
- **手动记录**：点「添加记录」填写日期、项目、任务、时长、是否计费
- 本周总工时、计费/非计费占比、每日柱状图实时更新
- 表格支持编辑、删除

---

## 7. 福利

- 顶部显示总预算、已用、剩余、已参与数量
- 按类别筛选：健康、身心健康、学习、财务、生活方式
- 每个福利可以「参与 / 退出」
- 有预算的福利可以「报销」：填写金额、描述、附加收据（仅文件名），提交后占用预算并发送通知

---

## 8. 发票与收款方式

### 8.1 发票

- 新建发票：客户、编号（自动递增）、货币、开具/到期日期、明细行（描述、数量、费率）
- 状态：草稿 / 已发送 / 已付款 / 已逾期
- 支持筛选、排序、复制、下载、打印、标记为已发送/已付款、删除
- 顶部统计显示未结清、逾期、已付款、草稿金额

### 8.2 收款方式

- 添加银行账户 / PayPal / Wise / 借记卡
- 只保存末 4 位，不保存完整卡号
- 可设默认方式、删除；删除默认方式时会自动顺延
- 显示下次打款日期与打款计划（周末/节假日提前到前一个工作日）

## 9. 设置

| 标签页 | 内容 |
|---|---|
| 通用 | 语言、每周起始日、时间格式（24/12 小时）、日历起始小时、显示周末 |
| 休假 | 合同天数、结转天数、查看政策、节假日列表 |
| 通知 | 邮件通知、浏览器推送、每周摘要 |
| 安全 | 修改登录密码 |
| 外观 | 浅色 / 深色主题 |
| 数据 | 导出 JSON、重置演示数据 |

所有设置自动保存；重置演示数据会恢复初始示例，并同步到服务器。

## 10. 修改密码

1. 「设置 → 安全」
2. 输入当前密码、新密码（至少 8 位）、确认新密码
3. 点「更新密码」

更新成功后，**其他设备上的登录会被强制退出**，当前设备保持登录。

如果忘记密码：目前没有自助找回。管理员可以在 Cloudflare D1 控制台删除该用户的会话，或创建一个新账号；后续可接入邮件重置。

---

## 11. 管理员上手指引

1. 用 `ADMIN_EMAILS` 里的邮箱注册 → 自动成为管理员
2. 让同事自行注册（默认员工）
3. 打开「团队审批 → 成员」，给需要审批的人设为「主管」，并给员工选择「直属上级」
4. 在「设置 → 休假」里调整全公司的合同天数、结转天数
5. 在「休假 → 查看节假日列表」里维护法定节假日（影响所有人的天数计算）

## 12. 数据、安全与已知限制

- **存储**：Cloudflare D1（SQLite），每张表按 `user_id` 隔离；接口层强制校验归属
- **鉴权**：邮箱 + 密码，PBKDF2-SHA256；会话令牌只存哈希，Cookie 为 HttpOnly / Secure / SameSite=Lax，14 天有效
- **同步**：前端本地状态 600ms 防抖后差分推送，最后一次写入生效（无冲突提示）
- **密码强度**：当前为 1 万次 PBKDF2 迭代，受 Workers 免费版 10ms CPU 限制；升级付费版后可把 `worker/auth.ts` 的 `ITERATIONS` 提到 60 万
- **文件**：只存元数据，不存内容
- **限流**：暂无登录失败限流，公网使用前建议加

## 13. 常见问题

**Q：登录后看到的是演示数据，能清空吗？**
A：「设置 → 数据 → 重置演示数据」会恢复示例数据；目前没有「清空全部」按钮，可以逐条删除，或在数据库中删除该用户。

**Q：切换语言后我的备注没变？**
A：只翻译内置演示内容；你自己输入的文字不会被翻译。

**Q：同事收不到审批通知？**
A：通知是站内通知（铃铛），不是邮件；邮件通知开关目前是演示用途。

**Q：为什么手机上周视图只有 3 天？**
A：小屏自动切成 3 天窗口，用 ←/→ 按 3 天步进。

**Q：上传的文档刷新后打不开？**
A：演示版不保存文件内容，仅保留元数据。

## 14. 本地开发与部署

```bash
npm install
npm run db:local      # 初始化本地 D1
npm run build         # 生成 out/
npm run worker:dev    # http://localhost:8787
```

线上部署：

```bash
npm run db:remote     # 应用表结构到远程 D1
npm run deploy        # next build + wrangler pages deploy
```

详细的架构与配置说明见根目录 `README.md`。
